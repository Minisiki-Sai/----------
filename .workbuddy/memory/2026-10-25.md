## 同日：评估「抓包/解析会被厂商检测到吗」（只读排查，未改代码）

技术事实：
- 抓包侧：Npcap 是 NDIS 轻量过滤驱动，只读副本，不拦截/不改包/不向游戏服务器发包 → 服务端协议层零痕迹。
- 解析侧：全仓唯一 `OpenProcess + ReadProcessMemory` 在 `live_dps/process_reader.py`，只被 `V576MemorySource` 使用，
  而 `V576MemorySource` 只由 `collector.start_memory()` 构造，`start_memory()` **无调用点**（死代码）；
  实际路径是 `start_npcap()`。对游戏进程只做 Toolhelp32 按名找 PID + GetExtendedTcpTable 查端口，**不开游戏进程句柄**。
  无 SetWindowsHookEx / 注入 / hook / 改文件 / 模拟输入；全局热键走 RegisterHotKey。
- 本机可见痕迹：① 本机已装 Npcap 内核驱动（`sc query npcap` = KERNEL_DRIVER RUNNING，drivers\npcap.sys）；
  ② 抓包期间持有 \Device\NPF_ 句柄；③ release 版 manifest 是 requireAdministrator（app-release-manifest.xml:17），进程高完整性；
  ④ 顶层悬浮窗 always_on_top+transparent+skip_taskbar；⑤ 本地产物目录 ~/Documents/DragonNestDpsCapture。
- 结论口径：服务端检测不到；本机侧取决于厂商是否部署内核反作弊/进程黑名单。被动只读比读内存/注入温和一个数量级。
- 未提供任何规避检测的手段。

## 同日：排查「游戏中按 F11/F12 有时不生效」（只读，未改代码）

热键是**双路径**，理解这一点才能解释「有时」：

| 场景 | 走的路径 |
|---|---|
| 游戏不在前台 | `tauri-plugin-global-shortcut`（RegisterHotKey） |
| 游戏在前台 | 后台线程 `start_foreground_game_hotkey_poller`，20ms 轮询 `GetAsyncKeyState` |

切换的闸门：插件回调里 `if foreground_game_process_id().is_some() { return; }`
—— 因为龙之谷会抑制 RegisterHotKey（代码注释已写明）。

六条会导致「按了没反应」的原因，按可能性排序：

1. **默认键是 `Alt+F12` / `Alt+F11`，不是单按 F11/F12**（`globalHotkeys.ts:1-2`）。
2. **修饰键严格相等匹配**（`lib.rs:540-551`）：按着 Shift / Ctrl / Win 再按热键即无效。
   游戏里按着 Shift 疾跑是常态。
3. **游戏前台的进程列表每 2 秒才刷新一次**（`lib.rs:563-568`）：刚切回游戏/刚启动
   客户端的前 2 秒，`game_foreground=false` → 轮询跳过，而插件又因「游戏在前台」return
   → **双路同时静默**。
4. **进程名白名单只有 `dragonnest.exe` / `dragonnest_reborn.exe`**（`lib.rs:602`）。
   客户端改名、私服版本、启动器转发都会让前台识别失败 → 只能靠 RegisterHotKey
   → 而游戏抑制它 → 全程不灵。
5. **F11 是「切换」不是「开」**：读 localStorage 的 `...buff-overlay-enabled`，
   记录与实际窗口状态不同步时第一下是关。
6. **统计处于 starting/stopping 时按 F12 不会重启**（`App.vue:99-105` 只在
   非 starting/running 时 startCapture）。

另有一处明确缺陷（未修）：`App.vue:130` 启动时 `configure_global_hotkeys` 失败被
`catch {}` 静默吞掉（注释还写着「Browser preview」），若 `Alt+F11` 被其他程序占用，
用户全程不知道热键没注册。设置页手动保存时会报错，启动时不会。

   → **游戏前台按热键确实不可靠，这是游戏输入保护导致的，不是注册问题**。

## 排查「进本后识别不到 Boss」：已定位，未修（等用户确认）

### 结论：不是认不出，是显示层按设计留空
悬浮窗顶部两行是两套证据：
- **副本行**：地图包（map）为主、攻击目标反推为兜底。实测正常 ——
  `capture_20261024_黑龙经典.dpscap` 从**城镇**开始录（地图历史：神圣天堂 → 黑龙巢穴经典 → 庭院），
  进本即识别 `black_dragon_classic`；`boss_actor_ids` 8 个全部由出场包绑定，
  `late_identity_seeds` 0 个。所以「先点统计再进本」不影响副本行。
- **Boss 行**：`overlay_boss_identity` 取值顺序 = 本机 15 秒目标 → 本机 30 秒目标 →
  本机「出过手」就留空 → 血量行 → 运行时目标 → 动作证据。

### 根因（已用两条对照实验证明）
`overlay_boss_identity` 里这句：

```python
if self_source_has_attacked(snapshot, self_source_id):
    return build("")
```

`self_source_has_attacked` 查 `displayAttackTargets` / `recentAttackTargets` /
**`lastAttackTargets`**（永久表，整个采集会话从不清空）。于是：
1. 本机只要出过手（含**进本前在城镇/路上清的小怪**），永久表就非空；
2. 之后停手超过 30 秒，两张带时效的表过期；
3. → 直接留空，**再也回不到血量行**（注释写的「本机从进本到现在一次都没出手」实现成了「整个会话没出过手」）。

### 实证脚本（都可重跑）
- `.dev/diag/prove_boss_row_blank.py`：只差「永久表有没有旧记录」两组输入，
  `Boss 行=''` vs `Boss 行='黑色戒指惩罚者梅鲁卡'`。
- `.dev/diag/prove_boss_row_idle.py`：走 `CombatAggregator.observe_attack_target` →
  `overlay_snapshot` → `overlay_boss_identity` 正式链路。打 Boss 中显示，
  停手 16/29 秒仍显示，**停手 36 秒变空**，90 秒仍空。
- `.dev/diag/diag_self_actor.py`：每 30 秒采样自机 actor / 地图 / Boss 数，
  确认进本换角色时 `current_self_actor_id` 有更新（0x4FAB276E → 0x4FAB816E），不是自机丢失。

### 为什么和「先点统计再进本」强相关
先点统计 = 抓包覆盖城镇段 = 城镇/路上的出手进了永久表 = 进本后到第一次打 Boss 之间
这一行必然空。若改成「进本后点统计」，永久表从空开始，未出手时能正确回落到血量行。

### 既有测试口径（修的时候别破坏）
`tests/test_boss_identity_follow_target.py::test_stopped_attacking_clears_the_row`
刻意锁住「停手后留空、不跳队友目标」。所以修法不能简单删掉这句，
要区分「本副本内出过手」与「进本前出过手」。

## 双链路识别改造（已实现 + 实测，本轮核心）

用户明确了设计口径：
- **A · 进本绑定（主）**：开着统计进图 → 拿到副本 + Boss → 直接绑白名单 Boss → 悬浮窗提示 + 播报。
- **B · 目标切换（切）**：只有攻击换了目标，才用聚合器 15 秒伤害占比收窄。

## 修复：回放时悬浮窗显示「统计已停止」

### 根因
悬浮窗窗口（BuffOverlay）**自己不访问后端**，只订阅主窗口推来的
`combat.snapshot`；这份快照的源头是 `/api/capture/buff-overlay`
（`overlayEventPublisher.pollCombat` → `simulatorApi.buffOverlayStatus`）。
而 `replaySource` 当时只接管了 `captureStatus` 和 `captureVoiceEvents`，**漏了这个接口**。

于是回放时 payload.state 仍是后端真实状态（idle/stopped）：
- `useBuffOverlayPresentation.ts:108` 的 `captureActive` 为 false；
- `useBuffOverlay.ts:51` 的 `skillCountdownRows` 直接返回 `[]`；
- `emptyStateText` 变成「统计已停止」。
→ 语音在念（走 voice-events，已被接管），悬浮窗却整块空白。

### 改动
1. `replaySource.replayBuffOverlayStatus()`：state→running、副本名/键→回放那场、
   elapsedSeconds→游标；并清掉上一场残留（bossName/bossHealth/players/endedBossIds）。
   保留 buffOptions（设置面板的增益目录要用）。
2. `api.buffOverlayStatus` 挂上这个包装（与 captureStatus 同样条件：`replayActive()`）。
3. **互斥保护**（回答「会不会影响主程序」）：回放接管接口期间若启动真实统计，
   抓包在跑但界面全是回放内容，看着像统计坏了。所以
   - `App.startCaptureWithOverlay` / `stopCaptureWithOverlay`：先 `stopReplay()`；
   - `ReplayView.startPlayback`：改为 async，先查真实状态，running 就先 `stopCapture()`。
4. 新增测试 `replaySource.test.ts`「悬浮窗快照也必须冒充正在统计」（含残留字段必须清空）。

### 实测（.dev/selftest/verify_overlay_replay.mjs，CDP 跑真实页面）
| 阶段 | overlayState | captureActive | 副本 |
|---|---|---|---|
| A 无回放 | idle | false | — |
| B 回放中 | **running** | **true** | 黑龙巢穴（三） |
| C 点停止后 | idle | false | — |
B 阶段 `endedBossIds` 为 0（上一场的结束标记已清，不会抹掉新行）。

### 结论
- 不影响主程序统计：包装只在 `replayActive()` 为真时生效，停止后立即回落到后端原值。
- 前端 233 pass / 6 fail（既有 overlayResizeScheduling×5 + qwenVoiceAssets×1）。
- 仍要重启后端（Python 不走热重载）；前端改动 Vite 会热更。

## 【已修】实战「语音不播 + 倒计时几秒消失」：watch 把副本名抖动当成换副本

### 铁证（sessions/20261025_204733，黑龙三，115 秒）
`frontend_countdown_trace`（本轮新加）显示 **nest 变化与行清空是同一行记录**：
```
t=27.359 count 0→1  nest='黑龙巢穴（三）'（未变）  recent=1
t=40.109 count 1→0  nest='黑龙巢穴（三）'→'黑龙经典'  recent=0  dead=0 retired=0
t=41.156 nest='黑龙经典'→'黑龙巢穴（三）'
... 每 1 秒来回跳（captureStatus 轮询周期），共 30+ 次
t=67.859 count 0→1（建立） → t=68.156 nest 变'黑龙经典' → count 1→0
```
`recent 1→0` 是 `clear()` 独有痕迹；`dead/retired` 全 0 排除 cancel/换边；
`state`/`clockRunning` 全程 running（`voice_state` 每秒采样）排除 reset 分支。
→ 唯一入口：页面 `watch(() => [props.running, props.live, props.nest], reset)`。

### 根因两层
1. **后端**：`_detected_nest` 的 key 是地图级 `map:14464`，进不了 `known_nest_keys()`，
   于是原条件「当前 key 不认识就允许覆盖」每秒成立 → `_inferred_nest` 把精确值顶掉，
   nestLabel 在「黑龙巢穴（三）」（地图精确）和「黑龙经典」（目标反推）之间交替。
2. **前端**：`props.nest` 一变就 `reset()` → 清掉全部时钟（含待播语音）。
   这场只有 34848 一种技能，其唯一语音「小追已好」挂在同一时钟上，
   所以倒计时闪一下就没 + 语音完全不播是**同一件事**。

### 修复
- 前端 `splitBossScope.nestScopeKey(nest, previous)`：只看副本类别（`countdownNest`），
  识别空档（空名字/城镇）保持上一次，不把「暂时认不出」当换副本。

### 教训（写给自己）

## 【已修】实战「语音不播 + 倒计时几秒消失」：watch 把副本名抖动当成换副本

### 铁证（sessions/20261025_204733，黑龙三，115 秒）
