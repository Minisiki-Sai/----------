## 启动卡顿排查（首次点击反应慢 / 调整位置首次显示不全）

**实测数据（打包版）**
- 引擎 `DataStore.load()` 0.33s、`NativeSimulatorCore` 2.63s，合计 ~3.2s。
- `v420_backend` 模块级 import 3.84s（其中 `live_dps/__init__` 1.5s、aggregator/sources 各 0.6s）。
- 旧 `/api/health` 也要先 `get_engine()`，而 `serve()` 又先建引擎再 `serve_forever`，
  所以窗口前 4~5 秒端口没在听，界面停在"正在唤醒解析核心"，按钮看着有但不响应。
- 单独跑 `DragonNestEngine.exe`：首 health 1.55s；经桌面壳启动：5.44s（壳在 WebView/托盘初始化之后才 spawn 引擎）。

**修改**
1. `get_engine()` 加 `_ENGINE_LOCK` + `_ENGINE_READY`，重复请求不再各建一次引擎。
2. `serve()` 绑端口后立刻起线程预热引擎，`/api/health` 不再触发引擎构造，返回 `ready` 标志。
3. `capture/status`、`capture/toggles` 在预热期直接返回 `starting` / 默认值，不再挂住请求。
4. 模块级重导入下沉到 `_engine_classes()`（引擎线程里导入）；`npcap_config.py` 从 `live_dps/` 挪到
   `dragon_nest_builder/`，避免 import 它时触发整个 `live_dps/__init__`（1.5s）。
   → 后端 import 3.84s → **0.27s**。
5. Rust `setup()` 第一行就 `start_backend`（原先在托盘/菜单/窗口注册之后）。
6. 前端去掉阻塞式启动页：主面板首帧即渲染，未连上时显示一条"正在唤醒解析核心，界面已可用"的浅色提示；
   `useLiveCapture` 在首次成功前不再把 fetch 失败写成红色"连接已断开"。
7. 语音轮询 100ms → 150ms；毛玻璃 blur 34px → 20px（遮罩 14 → 10px）减少每帧重绘。
8. 「调整位置」首次显示不全：进布局模式后按 0/120/400/900ms 多次重测尺寸（冷启动 WebView 首帧几何为空）。

**注意**：改 CSS/TS 之后必须重跑 `-SkipEngine` 的完整构建；本机 cargo 增量链接约 15~30 分钟。

**追加：把引擎提前到创建窗口之前**
- `run()` 里在单实例锁之后、`initialize_session` 之前预启动引擎（仅 release），
  `setup` 直接复用预启动的子进程（`prelaunched.or_else(|| start_backend(&root))`），
  避免「先 WebView 后引擎」串行。
- 实测（打包版）：首 health 5.10s → 2.86~3.87s；ready 8.13s → 5.57s。
  引擎单独启动 1.55s；剩余时间主要是 Windows 加载/扫描 36MB exe + WebView2 冷启动。
- 最终包 88.1MB / zip 55.3MB，engine 50.2MB；`target`、`outputs`、`dist` 已清。

## 「调整位置」悬浮窗显示不全（截图复现）

现象：点「调整位置」后窗口气泡出现，只有 1 行内容，下方一大块空白，且没有拖动条/完成按钮；
再点一次才正常。

根因：两个叠加
1. `adjustOverlayLayout()` 先 `set_buff_overlay_visible(true)`（冷启动时才创建 WebView2 窗口），
   紧接着 `emitTo` 发 `buff-overlay-layout-mode=true`。冷窗口的监听器还没注册 → 事件丢失，
   窗口停在普通模式：没有拖动条，也不会按预览内容重算尺寸。
2. 窗口尺寸是持久化的：上次布局模式留下的 3xx×240 尺寸被复用，而普通模式只有 1 行内容，
   于是出现"一行内容 + 大片空白"。

修复
- `broadcastLayoutMode()`：进入布局模式按 0/150/400/900/1600 ms 重发 true（幂等），退出按 0/200 ms 发 false；
  新一次广播前清掉旧定时器，避免"完成调整"被迟到的 true 覆盖。
- `useBuffOverlay.setLayoutMode()` 离开布局模式时也做 0/120 ms 两次重测，把窗口缩回内容高度。
- 之前那版的 0/120/400/900ms 重测只解决"尺寸算小了"，没解决"事件没到"，所以第一次点仍然错。

## 调整位置：定时重发仍不够，改用共享 localStorage 标志

用户 14:54 的包已包含「多次重发事件」版本（0/150/400/900/1600/2400/3600/5000ms），
截图显示仍然只有 1 行、没有拖动条 —— 说明这台机器上按需创建的悬浮窗 WebView 从
`set_buff_overlay_visible` 到页面 onMounted 注册监听 > 5s，事件重发仍然全部落空。

改成**不依赖时序**的方案：
- 新增 `frontend/src/utils/overlayLayoutFlag.ts`，key 为
  `dragon-nest-v420-overlay-layout-mode`。三个窗口同源同一 WebView2 profile，localStorage 共享。
- 主窗口 `adjustOverlayLayout()`：先 `writeOverlayLayoutMode(true)`，再 show 窗口，再广播事件。
- 悬浮窗 onMounted（`componentMounted = true` 之后）读一次标志，同时
  `onOverlayLayoutModeChange()` 订阅跨窗口 `storage` 事件，两边都走 `setLayoutMode()`。
- `finishOverlayLayout()` 写 false + 广播 false。
- 事件通道保留，负责已打开窗口的即时切换；标志负责冷窗口。

教训：跨窗口事件不能假定窗口已就绪，尤其 WebView2 冷启动在这台机器上可能要数秒。
