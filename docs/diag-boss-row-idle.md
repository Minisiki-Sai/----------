## 二、问题 1：`未识别实体 4181013`

### 复现证据

```
=== capture_20261024_黑龙硬核.dpscap ===
t= 882.7s on_junk  name='未识别实体 4181013'  tpl=4181013  target=0x000000EE@4181013
t= 884.7s on_junk  name='未识别实体 4181013'  tpl=4181013  target=0x000000EE@4181013
t= 886.7s idle     name='未识别实体 4181013'  tpl=4181013  target=0x000000EE@4181013
t=1007.6s on_junk  name='未识别实体 4181013'  tpl=4181013  target=0x000000FE@4181013
t=1009.6s on_junk  name='未识别实体 4181013'  tpl=4181013  target=0x000000FE@4181013
```

### 根因链

1. 模板 `4181013` **不在** `monster_templates_v576.json` → `core_decoder` 兜底命名
   `f"未识别实体 {template_id}"`（`core_decoder.py:1507`）
2. 它也**不在** `black_dragon_hardcore.template_ids`（18 个：4180002-4182008 段，没有 4181013）
3. 本机在打它 → `overlay_boss_identity` 层级 0：
   ```python
   target_is_boss_template(mine_id) is not False   # 未收录 → None → 放行
   and attack_target_is_current(...)               # 10 秒内打过 → 成立
   ```
   设计上是**故意的**（注释：否则新副本/新关卡 Boss 会被挡掉），代价是未收录实体能占 Boss 行
4. `ranked()` → `is_addable()` 非 strict → `None` 也接受 → `name_for()` 拿到 `未识别实体 4181013`
5. 结果这一行直接显示内部代号

### 方案对比

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 补数据** | 把 4181013 录入 `monster_templates_v576.json` + `black_dragon_hardcore.template_ids` | 根治，名字正确，还顺带让它能参与 focus 判定 | 需要确认它的真名（游戏内看一眼，或从相邻模板推断）；只解决这一只 |
| **B 展示层兜底** | 名字匹配 `^未识别实体\s*\d+$` 时不显示，改用占位「未知首领」 | 任何未收录模板都不再露内部 id | 仍是占位，用户还是不知道是谁 |
| **C 收紧准入** | 未收录模板（`target_is_boss_template` 返回 `None`）不许占 Boss 行 | 从根上挡住杂兵/未知实体 | **会踩旧坑**：新副本新关卡 Boss 全部显示不出来，Boss 行卡在上一关 |

**建议 A + B**：先补 4181013 的数据（A），再加 B 作为通用兜底。C 不要做，注释里已经写明为什么。

## 三、问题 2：停手时 Boss 行跟随队友目标

### 复现证据

```
海龙 1     停手采样 356 次，其中 follow_peer=True 130 次（37%）
黑龙经典   停手采样 770 次，其中 follow_peer=True 198 次（26%）
```
（`follow_peer=True` = 这一行显示的模板，等于某个队友此刻的目标，而不等于本机最后目标）

### 根因链

`overlay_boss_identity` 的取值顺序：

```
层级 0：本机目标 —— 但要求 attack_target_is_current()，窗口只有 10 秒
层级 1：party_boss_health() 里 updatedSeconds 最新的血量行 ← 队伍在打的
```

本机停手超过 10 秒 → 层级 0 失效 → 掉到层级 1 → 血量行按"谁最新"排序 → **队友在打的那只胜出**。

这是**原始设计意图**（注释：「停手时显示队伍进度」），不是编码错误。但它和用户直觉冲突：
不打怪的时候，这一行会莫名跳到别人在打的目标。

### 方案对比

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 与 focus 同源** | 层级 0 改用「本机 15 秒 dominant 目标」，再用「本机最后一次目标」兜到 30 秒；完全无目标才回落血量行 | Boss 行与语音播报同一套判断，停手不再跳；顺带修掉换边后不跟 | 本机打完一只后停手，这一行会多挂 30 秒 |
| **B 只延长窗口** | `attack_target_is_current` 的窗口 10s → 30s | 1 行改动 | 治标，30 秒后照跳 |
| **C 不改** | 保持"队伍进度"语义 | 零风险 | 用户观感不变 |

**建议 A**。理由：本次已经引入 focus 白名单，Boss 行理应跟着同一条"我在打谁"的判断走；
两条链路（播报/显示）用两套时效（15s / 10s）本身就是不一致的来源。
`attack_target_is_current` 的 10 秒窗口是分边时代留下的，现在有 `attackScores` 可以给更稳的依据。

## 四、问题 3：Boss 行显示队友名字（未复现）

### 已知的两条理论路径

1. **`targetNames` 全局表污染**
   `incoming_damage` 事件（`source_id="__incoming_damage__"`，`target_id` = 被打的玩家，
   `target_name` = 玩家名，`amount > 0`）会进入 `observe_attack_target` →
   写 `_overlay_target_names[玩家actor] = 玩家名`。
   而 `name_for()` 会先按**裸 actor id** 查这张表 —— 若某个 Boss 的 actor id 与某个玩家
   相同，就会顶着玩家名显示。

2. **`damage_targets` 混入玩家**
   层级 3 用 `strict=True`，玩家没有 `@模板` → `target_is_boss_template` 为 False → 被拦。**这条安全。**

### 实测结论

4 个包（黑龙硬核 / 黑龙经典 / 梦魇海龙 / 沙龙硬核）全量扫描：

```
incoming_damage 事件 0 条
targetNames 未混入玩家名。
```

即本批数据**没有触发**。路径 1 仍然是真的（代码允许），只是需要"玩家 actor id 与 Boss actor id 撞号"才会显形，概率低。

**建议**：顺手做防御，不改行为——`name_for()` 查 `targetNames` 前，先确认该 target 是 Boss 模板
（`target_is_boss_template(target_id) is not False`），避免玩家名/eid 串到 Boss 行。

## 七、已实施：按「A」方案落地（2026-10-25）

### 口径

> 停手时保持「我最后打的那只」，最多挂 **30 秒**；超过就留空，前端显示「未识别」。
> 不再回落到队友正在打的目标。

### 改动

| 文件 | 改动 |
|---|---|
| `live_dps/aggregator.py` | 新增 `_DISPLAY_TARGET_TTL_MS = 30_000` 与快照字段 `displayAttackTargets` |
| `native/overlay_service.py` | `overlay_boss_identity` 取值顺序重写：① 15s 本机目标 → ② 30s 本机目标 → ③ **本机出手过就返回空** → ④ 仅在本机从未出手时才走血量行/伤害行/动作行；删除分边"最多人在打"投票分支 |
| `frontend/src/utils/overlayIdentity.ts` | `bossName` 为空且状态 `unknown` 时显示「未识别」，不再是空白行 |

关键判据 `self_source_has_attacked()`：三张表（`displayAttackTargets` / `recentAttackTargets` /
`lastAttackTargets`）任一命中本机即为真。用**永久表**保证「我打过」这件事整局不会被遗忘，
停手后才会留空而不是跳去显示队友。
