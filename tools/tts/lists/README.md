# 语音包生成清单（158 句）

给新音色（豆包 小何2.0 / Vivi2.0 等）批量生成语音时用。内容来自
`frontend/public/voices/qwen3/manifest.json`，**一条不多、一条不少，顺序与原清单一致**。

## 文件说明

| 文件 | 用途 |
|---|---|
| `01_phrases_plain.txt` | **主清单**。每行一句，直接整段复制给 TTS 工具 |
| `02_phrases_indexed.txt` | 带序号，逐条核对/定位用 |
| `03_phrases.csv` | 序号 + 文案 + 字数 + 目标文件名，Excel 可开，改名对表用 |
| `04_batches.txt` | 按每 20 句分 8 批，批量工具限条数或想分批试听时用 |

规模：**158 句 / 1067 字**，平均 6.8 字，最短 1 字（`跳`），最长 16 字。

## 生成参数

| 项 | 建议 | 原因 |
|---|---|---|
| 格式 | **wav**（PCM）优先 | 本机没有 ffmpeg，mp3/m4a 转不了 |
| 声道 | 单声道 | 立体声也能自动转，但没必要占体积 |
| 采样率 | 24kHz 或以上 | 程序用 24kHz，低采样率会发闷 |
| 语速 | **0.9 ~ 1.0**，别低于 0.85 | 现有音色 158 句总量约 292-297 秒，慢 30% 会拖乱节奏 |
| 情感/风格 | **关闭**，用中性朗读 | 带情感的句尾有余韵拖音，预警播报需要短促收住 |

## 抽听必查的 10 句（专有名词最容易读错）

生成完不要全量听完，只抽这 10 句。读音错了后续 158 句都得重来。

```
跳                                   ← 单字最容易吞音/拖长
注意狙翎点名                          ← 「狙翎」jū líng，极易读成 zǔ
注意曜点名                            ← 「曜」yào
注意烈点名                            ← 「烈」liè
注意噬魂者点名
注意炼金圣士点名
注意影舞者点名
叹息之墙已好，前往点位
注意砸地                              ← 「地」必须是 dì，不能读轻声 de
马上飞天、注意躲避龙息消灭暗影            ← 最长句，听句尾有没有拖
```

如果个别字读错，优先在文本里换写法（如「砸地」→「砸低」）。**改过写法的句子必须回写到
manifest，否则运行时匹配不到、该条直接静音。**

## 命名规则（三选一）

1. **hash 命名**（最省事，0 改名）：用 `03_phrases.csv` 的「目标文件名」列改名，或直接用
   `tools/tts/volc_tts.py` 批量生成，它自动按 hash 写盘。
2. **句子命名**：文件叫 `注意冰眼.wav`、`即将冰眼.wav`，`tools/tts/ingest.py` 会自动匹配
   （空格、中英文标点、全半角都会被忽略）。
3. **序号命名**：`001.wav`、`002.wav`… 配合 `02_phrases_indexed.txt` 的序号对应，
   再用 `ingest.py --list` 指定清单。

## 在火山体验页批量生成（浏览器脚本）

体验页一次只能输入一句，158 句手工点不现实。用 `console_autofill.js` 自动填句、自动点合成、自动收音频。

1. 打开 https://console.volcengine.com/speech/new/experience/tts ，**先在页面上选好音色**（脚本不碰音色）
2. F12 → Console，输入 `allow pasting` 回车（否则 DevTools 拒绝粘贴）
3. 粘贴 `console_autofill.js` 全文，回车 —— 自动进入**诊断模式**，不会点任何按钮
4. 按提示在页面上手动合成一句（如「注意冰眼」），等 30 秒看诊断结果
5. 诊断到音频后执行：

```js
DNACT.start()              // 跑全部 158 句
DNACT.start({ from: 21 })  // 从第 21 句续跑
DNACT.retry()              // 只重跑失败项
DNACT.stop()               // 中止
DNACT.zipNow()             // 手动打包本次采集的音频
DNACT.status()             // 看进度
```

**页面实测特征（2026-10 版控制台）**，脚本已针对这三条做过适配：

| 实测 | 影响 | 脚本对策 |
|---|---|---|
| 输入框是 `div.tiptap.ProseMirror`（富文本） | 直接改 `value` 无效 | `execCommand('insertText')` → 伪造 `paste` → 直接赋值，三路兜底 |
| 合成结果输出 **mp3**（`ID3` 头） | 程序要 `RIFF` 头的 wav，测试会卡 | 浏览器内用 WebAudio 解码 → `OfflineAudioContext` 重采样到 24kHz → 重封装 wav，不依赖 ffmpeg |
| 页面**没有**显式「合成」按钮（输入后自动合成） | 按文字找按钮找不到 | 先等 6 秒自动合成，再试候选按钮，最后试 `Ctrl+Enter` / `Enter` |

跑全量前先 `DNACT.start({limit:3})` 验证 3 句，看一眼日志里的 `触发：自动/按钮/快捷键` 计数，就知道靠哪条路成功。

全部成功会自动下载 `voice_pack_158.zip`，文件名已是 manifest 的 hash，解压后直接入库。

注意：
- 浏览器可能拦截「多文件下载」，本脚本只下载**一个 zip**，不会触发拦截
- 脚本靠钩子拦音频字节（fetch / XHR / blob / WebAudio / `<audio>`），页面若用 MediaSource 流式播放可能抓不到，诊断会明确告诉你
- 采集按「一句话一次合成」串行跑，158 句约 8-15 分钟，中途别切走标签页

## 硬约束

- **158 句必须全覆盖。** 少一句，那条播报在实战里完全不出声，不报错、不回退系统语音。
- 4 个音色目录都要有，且**内容不能是同一个文件复制四份**（`frontend/tests/qwenVoiceAssets.test.ts` 会校验）。
- 单个 wav 必须 > 12000 字节（约 0.25 秒 24kHz/16bit 单声道），太短会被测试判为异常。
